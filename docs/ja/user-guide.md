## 概要

Briclaude は Databricks Apps 上で動作する Claude Code ライクな AI チャットアプリケーションです。ユーザーは自然言語でコード作成や Databricks ワークスペースの操作を Claude に依頼できます。

### アーキテクチャ概要

```
┌─────────────────────────────────────────────────────────────┐
│                    Databricks Apps                          │
│  ┌─────────────┐         ┌─────────────────────────────┐   │
│  │ 認証プロキシ │ headers │ Briclaude API              │   │
│  │             │────────▶│ ├─ /api/* (API)             │   │
│  │             │         │ └─ /*     (フロントエンド)    │   │
│  └─────────────┘         └─────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

## ファイルシステムとユーザー環境

### ユーザー環境の分離

Briclaude では、各ユーザーに専用のファイルシステム領域が割り当てられます。これにより、ユーザー間のデータ分離が保証されます。

```
${USER_BASE_DIR}/
├── user1/                          # ユーザー1のホームディレクトリ
│   ├── .claude/
│   │   ├── settings.local.json     # Claude 設定
│   │   └── skills/                 # ユーザーのスキル
│   │       ├── my-skill/
│   │       │   └── SKILL.md
│   │       └── another-skill/
│   │           └── SKILL.md
│   ├── session_xxx.../             # セッション作業ディレクトリ
│   └── session_yyy.../
└── user2/                          # ユーザー2のホームディレクトリ
    └── ...
```

### ディレクトリの役割

| ディレクトリ | 説明 |
|-------------|------|
| `${USER_BASE_DIR}/${userId}` | ユーザーのホームディレクトリ。すべてのユーザーデータはここに格納 |
| `${userHome}/.claude/` | Claude 関連の設定ファイル |
| `${userHome}/.claude/skills/` | ユーザーが作成・インポートしたスキル |
| `${userHome}/${sessionId}/` | セッションごとの作業ディレクトリ |

### スキルとファイルシステム

スキルはファイルシステムに保存されるため、以下の特性があります:

- **永続性**: スキルはセッション終了後も保持されます
- **ユーザー固有**: 各ユーザーは自分専用のスキルを持ちます
- **ポータビリティ**: Git リポジトリからのインポートが可能です

## 認証とトークン

### 認証フロー

Databricks Apps では、認証プロキシがユーザーの認証を処理し、以下のヘッダーをアプリケーションに転送します:

| ヘッダー | 説明 |
|---------|------|
| `x-forwarded-user` | ユーザー ID (IdP から) |
| `x-forwarded-preferred-username` | 表示名 |
| `x-forwarded-email` | メールアドレス |
| `x-forwarded-access-token` | OBO (On-Behalf-Of) トークン |

### トークンの種類と用途

Briclaude では複数のトークンタイプを使用します:

#### 1. OBO (On-Behalf-Of) トークン

- **取得方法**: Databricks Apps の認証プロキシが自動的に付与
- **用途**: ユーザーの代理として Databricks API を呼び出し
- **有効期間**: リクエストごとに付与される短期トークン
- **制限**: Databricks Apps 経由のアクセス時のみ利用可能

#### 2. PAT (Personal Access Token)

- **取得方法**: ユーザーが Databricks UI で生成し、アプリに登録
- **用途**: Claude がユーザーの代理として Databricks CLI コマンドを実行
- **有効期間**: ユーザーが設定（推奨: 90日以内）
- **保存**: AES-256-GCM で暗号化してデータベースに保存

#### 3. Service Principal トークン

- **取得方法**: アプリケーションが OAuth Client Credentials で取得
- **用途**: PAT が登録されていない場合のフォールバック
- **制限**: Service Principal の権限範囲内のみ操作可能

### なぜ PAT が必要なのか

Claude Code がセッション内で `databricks` CLI を実行する際、以下の理由から PAT が必要です:

1. **CLI 認証**: `databricks` CLI はファイルシステム上の認証情報を使用します
2. **ユーザー権限での実行**: OBO トークンは HTTP ヘッダー経由でのみ利用可能で、CLI では使用できません
3. **ワークスペース操作**: ファイルのアップロード/ダウンロードにはユーザー権限が必要です

```
┌────────────────────────────────────────────────────────────────┐
│  Claude Code セッション内での認証                              │
│                                                                │
│  ┌─────────────┐    ┌─────────────────┐    ┌──────────────┐  │
│  │ Claude Code │───▶│ databricks CLI  │───▶│ Databricks   │  │
│  │             │    │ (PAT 使用)       │    │ Workspace    │  │
│  └─────────────┘    └─────────────────┘    └──────────────┘  │
└────────────────────────────────────────────────────────────────┘
```

### PAT の登録方法

1. Databricks UI で Settings > Developer > Access tokens から PAT を生成
2. Briclaude の設定画面でトークンを登録
3. トークンは暗号化されて安全に保存されます

**注意**: PAT は `dapi` で始まる形式である必要があります。

## 権限と操作の対応表

各操作で使用される権限/トークンは以下の通りです:

| 操作 | 使用トークン | 説明 |
|------|-------------|------|
| **アプリへのアクセス** | OBO トークン | Databricks Apps 認証プロキシが処理 |
| **セッション作成** | アプリ認証 | アプリ内部処理、ユーザー認証のみ必要 |
| **スキル一覧/作成/削除** | アプリ認証 | ファイルシステム操作、ユーザー認証のみ |
| **スキル Git インポート** | アプリ認証 | 公開リポジトリのクローン |
| **Claude チャット** | アプリ認証 + Anthropic API | Claude API 呼び出し |
| **Workspace ファイル取得** | PAT または OBO | `databricks workspace export-dir` コマンド |
| **Workspace ファイル同期** | PAT | `databricks sync` コマンド (Claude 実行) |
| **SQL Warehouse クエリ** | PAT または SP | Databricks SQL 実行 |

### 認証の優先順位

Databricks API を呼び出す際の認証方式は以下の順序で選択されます:

```
1. ユーザー登録の PAT (利用可能な場合)
   ↓ (なければ)
2. Service Principal トークン (OAuth M2M)
```

## スキルシステム

### スキルとは

スキルは Claude の能力を拡張するためのカスタム指示セットです。SKILL.md ファイルに記述され、Claude がタスクを実行する際に参照します。

### スキルの構造

```yaml
---
name: my-custom-skill
description: このスキルの説明
metadata:
  version: 1.0.0
  author: your-name
  source: https://github.com/org/repo  # Git インポートの場合
---

# スキル内容

ここに Claude への指示を Markdown 形式で記述します。
```

### スキルの保存場所

スキルはユーザーのファイルシステム領域に保存されます:

```
${userHome}/.claude/skills/
├── skill-name-1/
│   └── SKILL.md
└── skill-name-2/
    └── SKILL.md
```

### スキルの管理

| 操作 | 説明 |
|------|------|
| 一覧表示 | 登録済みスキルを確認 |
| 作成 | 新規スキルを作成 |
| 編集 | 既存スキルの内容を更新 |
| 削除 | 不要なスキルを削除 |
| Git インポート | 公開リポジトリからスキルをインポート |

### Git からのインポート

公開 Git リポジトリからスキルをインポートできます:

- **対応形式**: HTTPS URL または SSH URL
- **ブランチ指定**: 特定のブランチからインポート可能
- **パス指定**: リポジトリ内の特定ディレクトリを指定可能

## セッションとワークスペース連携

### セッションの仕組み

各チャットセッションには専用の作業ディレクトリが割り当てられます:

```
${userHome}/${sessionId}/
├── .claude/
│   └── settings.local.json  # SessionStart フック設定
├── imported_file1.py        # Workspace からインポートしたファイル
└── imported_file2.sql
```

### SessionStart フック

セッション開始時に自動実行されるコマンドを設定できます。Databricks Workspace をソースとして指定した場合、以下のコマンドが自動設定されます:

```bash
databricks workspace export-dir "/Workspace/path/to/source" . --overwrite
```

これにより、セッション開始時に Workspace のファイルがローカルにダウンロードされます。

### Workspace への操作方針

Briclaude では、Workspace やアプリの操作は **Claude Code に実行させる** 方針を採用しています:

```
┌────────────────────────────────────────────────────────────────┐
│  ワークスペース操作フロー                                       │
│                                                                │
│  ユーザー: 「このコードを修正して Workspace に保存して」        │
│      ↓                                                         │
│  Claude: ファイルを編集                                        │
│      ↓                                                         │
│  Claude: databricks sync で Workspace に同期                   │
│      ↓                                                         │
│  Claude: 「完了しました」と報告                                 │
└────────────────────────────────────────────────────────────────┘
```

#### この方針の利点

1. **柔軟性**: Claude が状況に応じて最適なコマンドを選択
2. **透明性**: 実行されるコマンドがユーザーに表示される
3. **エラーハンドリング**: Claude がエラーを解釈して対処
4. **学習**: ユーザーが CLI の使い方を学べる

#### 主な Databricks CLI コマンド

Claude がセッション内で使用する主な CLI コマンド:

| コマンド | 用途 |
|---------|------|
| `databricks workspace export-dir` | Workspace からファイルをダウンロード |
| `databricks workspace import-dir` | Workspace にファイルをアップロード |
| `databricks sync` | ローカルと Workspace を同期 |
| `databricks fs` | Unity Catalog Volumes 操作 |
| `databricks clusters` | クラスター管理 |
| `databricks jobs` | ジョブ管理 |

## セキュリティ

### データ分離

#### Row-Level Security (RLS)

データベースでは PostgreSQL の RLS を使用して、ユーザーが自分のデータのみにアクセスできるよう制限しています:

- **セッション**: 自分のセッションのみ閲覧可能
- **トークン**: 自分のトークンのみ管理可能
- **設定**: 自分の設定のみ変更可能

#### ファイルシステム分離

- 各ユーザーのファイルは `${USER_BASE_DIR}/${userId}` 配下に隔離
- パストラバーサル攻撃を防止するバリデーション実装
- セッション削除時は該当ディレクトリのみ削除

### トークンの保護

#### 暗号化

PAT などの機密トークンは AES-256-GCM で暗号化して保存:

- **アルゴリズム**: AES-256-GCM（認証付き暗号化）
- **鍵長**: 256ビット（64文字の16進数）
- **IV**: 暗号化ごとにランダム生成

#### 表示時のマスキング

UI でトークンを表示する際は部分的にマスク:

```
dapi****xyz  (先頭4文字 + 末尾3文字のみ表示)
```

### 入力バリデーション

#### スキル名

- 使用可能文字: `a-z`, `A-Z`, `0-9`, `-`, `_`
- パス区切り文字 (`/`, `\`) は禁止
- `.` や `..` は禁止

#### Git URL

- `https://` または `git@` で始まる URL のみ許可
- ブランチ名のバリデーション

### セッションセキュリティ

- セッション ID は TypeID 形式（UUIDv7 ベース）
- セッションごとに独立した作業ディレクトリ
- 他ユーザーのセッションにはアクセス不可
